## Findings

### Major — Forced pass is absent when the active player has no legal movement

- Canonical fact ID: `TURN-01`, supplemented by the approved forced-pass human decision.
- Evidence type: `human_decision`.
- Exact controlling text, `canonical_rulefacts.md`, “Proposed BoardBench interface conventions”:
  > “Human decision 2026-07-17: if and only if a player has no legal movement, expose one forced pass that advances the turn.”
- Related rulebook quote, page 1, “Der Spielablauf”:
  > “Die Spieler sind abwechselnd an der Reihe. Schwarz fängt immer an.”
- Conflicting symbols/transitions: `Game.legal_actions`, `Game.apply_action`.
- Expected: A nonterminal state with no legal movement exposes exactly one forced-pass action; applying it changes `player` and leaves the board and ejection counts unchanged.
- Implemented: `legal_actions()` returns an empty tuple. `apply_action()` accepts only actions present in that tuple, so the game cannot advance.
- Classification note: This is adjudication-dependent and visibly separate from printed-rule contradictions. The PDF itself does not specify what happens when no movement exists.

### Minor — Malformed action structures can escape the documented validation error

- `Game.action_to_name()` validates only the outer tuple shape and `"move"` tag.
- An invalid direction index can raise `IndexError`, and malformed/empty groups may raise other incidental exceptions instead of `ValueError("invalid action")`.
- This does not affect actions generated by `legal_actions()` and is therefore localized interface robustness, not a game-rule error.
